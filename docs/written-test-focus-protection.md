# 笔试焦点屏蔽

焦点屏蔽默认开启，可在“悬浮窗设计器 → 笔试悬浮窗”或笔试阅读器的“焦点屏蔽”开关中修改。设置保存在本地，切换布局不会重置。

- 笔试运行期间，主窗口不可获取焦点；重复启动应用不会唤起主窗口。
- 题目、回答、截图按钮和快捷操作窗口沿用不激活的悬浮窗机制。截图用途使用按钮选择，避免打开原生下拉弹窗。
- 在阅读器里操作按钮需要使用“内容可交互”模式，或按住设置中的临时交互修饰键（默认 Ctrl）；独立截图按钮始终可点击。
- 关闭屏蔽时恢复主窗口的可激活状态，但不会立即将其唤起。结束笔试或启动失败时恢复并显示主窗口。

此功能管理本应用窗口的焦点行为。用户主动切换应用、系统弹窗及其他应用自身引起的焦点变化不在其控制范围内。

## 0.1.3 验证

- 修复阅读器继承 `pointer-events: none`，导致开关和截图用途按钮无法点击的问题。窗口的鼠标穿透仍由原生交互模式控制。
- 避免对已经不可激活的悬浮窗重复调用 `setFocusable(false)`；Windows 下该调用会同时执行窗口停用，可能改变前台窗口。
- 自动化测试：938 项通过，2 项可选外部数据测试跳过；所有工作区 TypeScript 检查通过。
- Windows 原生验证使用独立进程的答题测试窗口，在 150% 缩放下发送真实鼠标输入，同时核对系统前台窗口句柄和答题窗口失焦事件。覆盖开关切换、重复启动、截图并生成答案、补图选择、结束确认和结束后主窗口恢复。
- 截图来自真实桌面，答案来自本地固定响应服务；该测试不调用付费模型，也不衡量模型回答准确率。

复现原生焦点测试：在项目根目录运行 `npm --workspace apps/desktop run written:focus-smoke`。测试使用临时数据目录，结果和阅读器截图写入 `artifacts/written-focus-smoke`。
