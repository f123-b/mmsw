# 项目库准确性升级：第一阶段

## 已实现的范围

- 新上传的项目题库默认待核验。重复导入保留原问题、原答案的确认/失效状态，新增答案独立待核验；不会批量修改历史确认状态。
- AI 生成项目题库复用 `isFactEligible`：过滤待审核、冲突、过期、无原文证据及跨项目事实。按事实类型和章节轮流选取，最多 80 条，避免前面的同类事实占满输入。
- 生成提示包含事实 ID、来源摘录、定位、归属、证据级别和结构化参数；不再注入未经相同准入规则过滤的项目理解摘要。资料中的文字不作为执行指令。
- 模型引用未知事实时整条候选不予接收，不再静默删除错误引用。保存前检查事实是否变化，以及明显的无依据数值、单位不符、无个人证据的职责和贡献夸大。通过筛查的生成内容仍为待确认。
- 项目答案确认在界面和数据库保存入口均做风险检查。无事实关联的手动/导入答案需要本人明确确认；这不意味着已获得机器证实。
- 项目题库增加“核验与来源”面板，显示关联事实、来源原文和风险；编辑时可选择关联事实。
- 现有数据库的事实关联按问题共享。修改关联时，同题其他答案标记失效待复核；本次明确确认的答案可以恢复。未修改关联的旧答案不受影响。
- 增加“本项目匹配自测（不调用 AI）”，使用已有严格项目题库匹配策略，检查具体问法是否命中已确认答案。

## 保持不变

不改变面试的严格/快速回答策略、模型调用热路径、通用题库确认规则、笔试模式、截图、快捷键、悬浮窗、共享保护及演讲稿。无需数据库结构迁移，无后台批量重写正式资料。

## 检查边界

自动核验是确定性风险筛查，并不是完整的自然语言事实验证。数值与单位相同也不能证明测试条件相同；个人职责中存在相关技术名词也不能证明整句贡献表述。所有新生成答案仍需人工逐句核对。无来源答案只代表本人确认，不代表系统有独立证据。

匹配自测衡量题库命中，不衡量模型最终回答质量。后续应使用用户真实项目、人工标注答案和连续追问构建独立评测集，再实施语义召回、候选重排和可选的依据事实作答模式。
